## Findings

- [ ] **RUN-001 (P1 protocol candidate, repeatable):** [strict H2](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45756151480/job/139695176565) reports HTTP/2 server must not send ENABLE_PUSH. Capture exact initial SETTINGS, value, order, frame and peer version. RFC 9113 §6.5.2 permits server value 0 but not 1; inspect decoder and state machine rather than altering valid peer. Verify H2 strict/fallback/reverse ALPN, omitted/zero/one setting, malformed settings, proper connection errors and no silent downgrade. H1 and H3 positive controls pass.
- [ ] **RUN-002 (P1 candidate):** [parallel multiplex](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376669387), [flow control](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376669341), [deadline](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376669438), [ping](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376669603); historical H2 multiplex/negotiation families may cascade from RUN-001, do not count separately before handshake fix. Observe peer events, same socket, stream IDs, independent body/status and flow-control windows; test cancel/reset/drain, HEAD, timeout, concurrent failures, no orphan streams.
- [ ] **RUN-003 (P1 candidate):** outbound [H2 HEAD](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376979305), [disconnect](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376983223), [H1 short](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376981265), [H1 retry](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376978479). Numeric dialer capture LAB-004 corrected; H1 GET now passes. Distinguish fixture from framing, retry safety, approved peer, redirect, timeout and response settlement. Preserve no blind replay and exact response bytes.
- [ ] **RUN-004 (P1 candidate):** [Foundation pool crash](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376705949), rate-limit/circuit [hosted job](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376706284), [hosted job](https://github.com/infocyph/infbyte-app-experiment/actions/runs/45661843498/job/139376708415). Trace runtime process and policy ownership; test worker recycle, cancellation, reaping, backpressure and lease recovery. See [Foundation](foundation.md).
- [ ] **RUN-005 (security integration):** Epicrypt remote JWKS needs approved peer identity across DNS/connect, see [EPC-001](epicrypt.md). Verify actual peer before HTTP bytes, verified TLS name, redirect reapproval, H1/H2/H3 parity. No bypass of caller security policy.
- [ ] **RUN-006 (retest):** QUIC provisioning corrected and native inbound/outbound H3 pass; dual-stack peer fixture fixed. Re-run all QUIC aggregate/flow/reset/drain cases, native admission and process/host/coroutine cases; extension availability is not a runtime defect.

## Candidate qualification branch

The `retry-after-head` contract refers to a response header already delivered, not the HTTP HEAD method. Both the PHP request producer and the shell verifier now use GET for this case; its exact one-request, status 200, partial body and error assertions remain unchanged. The isolated `qa/runwire-production-feedback` branch adds a candidate-only workflow that derives the two runtime matrices (256 + 51 = 307) from the existing frozen workload list, with unchanged worker definitions and PHP 8.5. It resolves the Runwire PR branch once for evidence and requires every workload to install that same source revision through normal Composer resolution (temporary inline alias, no release or dependency SHA pin); it also verifies identity after the workload. All other production jobs retain normal published package resolution. No result claimed yet: a request file on this branch must trigger qualification after upstream readiness. The five named hosted modes are present in the 307 cases; native/portable acceptance is also tracked by upstream hosted checks. Published-package acceptance remains required after release.

Candidate qualification scope correction: retain the full 307 runtime tuples and add all six existing remote-JWKS/DNS authentication tuples (313 total) from the frozen matrix, not new routine cases. Authentication reuses the same optional branch-based Composer resolution and pre/post installed source verification as runtime. The request file carries an expected candidate reference for evidence only; prepare verifies the live branch still matches it before any worker starts. This avoids accidental qualification of an intervening commit without pinning a Composer dependency. No production main change or release. Launch after the Runwire branch passes full hosted QA.

G security attribution: the original six authentication cases use curl/Guzzle, so installation of Runwire alone would not prove its transport. In the five isolated DNS namespace cases, additionally run the same Epicrypt RemoteJwks assertions using a test-only PSR-18 bridge over real Runwire AsyncDnsResolver/HappyEyeballsDialer, public address policy, exact URI allowlist, authenticated TLS H1 exchange and kernel peer evidence before HTTP bytes. Retain original Guzzle results and require both outcomes; reset phase and counters between transports. No production adapter, proxy bypass, external network access or relaxed assertion. Existing remote-JWKS cache/rotation case remains the independent curl control. Hosted validation pending.
