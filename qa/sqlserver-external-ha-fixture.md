# SQL Server external automatic failover acceptance

The existing two-replica read-scale fixture uses CLUSTER_TYPE=NONE and tests explicit manual promotion. It is not an automatic HA test. The new opt-in workflow uses a preprovisioned disposable three-data-replica SQL Server Linux/Pacemaker cluster, with synchronous commit, EXTERNAL failover, quorum and working fencing. The stable listener must follow the promoted primary. The test requests a native Pacemaker fence/reboot of the current primary; it does not execute ALTER AVAILABILITY GROUP or manually promote a replica. This is a fenced-node automatic promotion contract, not a claim that every spontaneous network partition is covered.

Provisioning is external and remains blocked until a dedicated reachable cluster exists. Use a protected GitHub environment named sqlserver-ha-lab restricted to main and trusted reviewers (the workflow also checks the branch). Provide environment variables SQL_HA_LISTENER (DNS name with trusted certificate, port 1433), SQL_HA_MANAGER (user@host on a surviving Pacemaker member; SQL server names must match cluster node names), and secrets SQL_HA_USER, SQL_HA_PASSWORD, SQL_HA_SSH_KEY, SQL_HA_KNOWN_HOSTS. The disposable database must be named infbyte_ha_lab, already joined to the availability group; the SQL principal needs DMV visibility, DDL in that database and DML. The SSH principal must be restricted to the required quorum, fencing and host identity commands on this dedicated cluster; do not configure production access. The runner must trust the listener certificate and be able to reach the management node and listener. Native fencing must be explicitly enabled and confirmed by the cluster. Keep all three data replicas synchronized before invocation. A failed run may leave its uniquely named test table or a degraded cluster; the fixture operator must reset/replace the disposable environment before retrying. No manual failover fallback is allowed.

Dispatch **SQL Server external clustered HA acceptance** with confirmation DISPOSABLE-HA-LAB only after the protected environment and fixture are ready. It verifies native topology, confirmed pre-fence rows, cluster fencing, a different primary via the original listener, exact ledger continuity, post-failover transaction callbacks and fresh-connection reads. It removes only its own table on success. The workflow is not part of routine hosted matrices and must not be counted as passed or as fully provisioned until executed.

Reference: https://learn.microsoft.com/sql/linux/business-continuity/availability-groups/cluster-pacemaker?view=sql-server-ver17
